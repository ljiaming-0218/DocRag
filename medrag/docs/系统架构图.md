# DocRAG 系统架构

## 总体数据流

```mermaid
flowchart LR
    UI[浏览器前端] --> API[FastAPI Routers]
    API --> AUTH[JWT 与资源归属校验]
    API --> JOB[Ingestion Job Service]
    JOB --> DB[(MongoDB)]
    JOB --> PARSE[PyMuPDF / OCR]
    PARSE --> SPLIT[Fixed / Recursive Splitter]
    SPLIT --> EMB[Embedding]
    EMB --> VS[(Chroma)]
    SPLIT --> BM25[BM25 索引]
    API --> CHAT[Chat Service]
    CHAT --> DB
    CHAT --> RW[Query Rewrite]
    CHAT --> ROUTE[Task Router]
    ROUTE --> SEARCH[Dense / Hybrid Search]
    SEARCH --> VS
    SEARCH --> BM25
    SEARCH --> RR[CrossEncoder Rerank]
    CHAT --> LLM[OpenAI-compatible LLM]
    CHAT --> UI
```

## 索引任务链路

```mermaid
sequenceDiagram
    participant F as Frontend
    participant R as PDF Router
    participant J as Job Service
    participant M as MongoDB
    participant P as Parser
    participant V as Chroma/BM25

    F->>R: POST /pdf/index
    R->>J: 校验用户、保存文件、计算 document_hash
    J->>M: 创建或恢复 job
    R-->>F: 202 + job_id
    J->>P: 解析 PDF，必要时 OCR
    P-->>J: pages + metadata
    J->>J: 切片、计算 index_fingerprint
    J->>V: 写入新的 index_generation
    J->>M: 校验并切换 active generation
    F->>R: GET /ingestion-jobs/{job_id}
    R-->>F: completed / failed + progress
```

`document_hash` 负责重复文件识别；`index_fingerprint` 负责配置一致性；`index_generation_id` 负责新旧索引切换。写入新代次失败时，旧 active 代次不应被提前删除。

## 问答链路

```mermaid
sequenceDiagram
    participant F as Frontend
    participant C as Conversation Router
    participant S as Chat Service
    participant M as MongoDB
    participant Q as Query Rewrite
    participant A as Agent Router
    participant R as Search Service
    participant L as LLM

    F->>C: POST /conversations/{id}/ask
    C->>S: query + token
    S->>M: 校验会话归属并读取最近历史
    S->>M: 保存用户原始问题
    S->>Q: history + query
    Q-->>S: rewritten_query 或原 query
    S->>A: 判断任务类型
    A-->>S: qa / summary / report / term / source_check
    S->>R: Dense 或 Hybrid 召回 + RRF + Rerank
    R-->>S: sources
    alt 无证据
        S-->>C: 固定拒答
    else 有证据
        S->>L: Prompt + sources + 有限历史
        L-->>S: answer
    end
    S->>M: 保存 answer、sources 和调试字段
    S-->>F: answer + sources + task_type
```

## 检索边界

```text
Query Rewrite
  → BGE query embedding / BM25
  → user_id + kb_id + optional document_ids 过滤
  → Dense 与 Sparse 候选
  → RRF 合并和去重
  → CrossEncoder 全局重排
  → evidence threshold
  → Prompt context
```

所有检索都必须保留 `user_id` 过滤。知识库会话不指定文档时检索整个知识库，指定文档时使用 `document_id in [...]` 限定范围。

## 模块边界

| 层 | 责任 |
| --- | --- |
| `routers/` | 请求校验、认证依赖、状态码和响应 |
| `services/` | 文档处理、索引、检索、Prompt、LLM 和会话编排 |
| `stores/` | MongoDB 连接、集合读写和索引 |
| `frontend/` | 上传、任务进度、会话、错误和 sources 展示 |
| `eval/` | 固定数据集、指标、Judge 和线上验收，不参与业务运行 |

## 当前风险

- Ingestion worker 仍在 FastAPI 进程内运行，尚非独立 worker 服务。
- 最新 20 题运行 20/20 执行成功；此前 15 个 HTTP 500 的运行与 MongoDB 连接故障相关，仍作为历史 Reliability 风险记录。
- OCR、Embedding 和 Reranker 的 CPU/网络成本尚未完成容量基准。
- 免费 Space 的本地 Chroma 和上传目录不保证长期持久化。
