## H2 运行方式（2026-10-16）

两个 PowerShell 终端分别运行；API 与 worker 使用相同的 MongoDB 配置、Chroma 路径和模型配置。MongoDB 必须支持事务（副本集或 mongos）；本地当前连接已确认是副本集。

```powershell

Set-Location D:\MedRag
D:\Anaconda\envs\medrag\python.exe -m uvicorn main:app --app-dir medrag/backend --host 127.0.0.1 --port 8000

# 终端 2：独立研究 worker
Set-Location D:\MedRag\medrag\backend
D:\Anaconda\envs\medrag\python.exe -m harness.research_worker
```

`POST /run` 现在返回 `queued`，不再在 API 进程内运行模型。没有启动 worker 时任务会等待；前端显示排队并允许取消。`POST /research-tasks/{task_id}/cancel` 只允许所有者操作，保留已提交证据与产物。

- `research_tasks` 保存固定范围、generation、`config_version=h2-v1`、累计预算、笔记/报告、待执行动作、恢复上下文和租约；`research_events` 按 `(task_id, action_id)` 唯一；`research_evidence` 按 `(task_id, evidence_id)` 唯一。
- worker 的租约为 30 秒，每 10 秒续租。事务将任务状态、事件和证据一起提交；租约 token 失效或任务已取消时，旧 worker 不能提交。恢复后复用已提交结果。
- 动作执行前先保存 action_id 和预算预留；中断后同一个动作最多执行两次尝试，每次都计工具预算，模型动作只计一次。笔记/报告与动作完成记录同事务提交，不会因中断重复追加。
- 模型响应未持久确认时记录 `model_response_unconfirmed`，保留已计费请求次数，再申请新一轮；无法获知的 Token 用量仍为 `unavailable`。
- 总时限从入队开始，排队和进程停机时间都计入原来的 180 秒；恢复不重置预算。generation 改变或旧索引不可用即停止，不静默改用新索引。配置版本改变时停止旧任务。
- 当前 Dockerfile 只启动 API，尚未部署独立研究 worker。部署时需配置独立进程及相同索引存储；本轮未修改线上部署。

## API

所有接口使用现有 JWT Bearer 认证。`user_id` 从令牌取得，不由请求体传入。

1. `POST /research-tasks`，返回 201。请求体：

   ```json
   {"kb_id":"<kb_id>","query":"比较知识库中的检索方法与限制","selected_document_ids":null}
   ```

   创建时固定文档列表和 active generation，检查每篇文档在当前 Chroma 中可读。返回的 `status` 为 `ready`。

2. `POST /research-tasks/{task_id}/run`，返回 202。仅所有者可启动，且只能从 `ready` 入队一次；独立 worker 领取执行。
3. `GET /research-tasks/{task_id}`，仅所有者可读。返回 `status`、`stop_reason`、预算计数、证据账本、笔记、报告和 `events`。任务运行时可轮询此接口。

## 首版约束

- 通过当前模型服务的原生 function calling 请求一次一个工具调用；零个、多个或非法调用均停止。允许的工具是 `search_documents`、`read_evidence`、`save_research_note`、`finish_report`。
- 模型不能指定用户身份、知识库或文档范围。每次取证重新检查固定 generation；失效即停止。
- 默认上限：8 个模型动作、12 次工具调用、180 秒。达到上限时保留已有证据和笔记，并记录停止原因。
- 研究运行另外记录实际发起的 `model_turns`。每次研究模型请求上限 45 秒，关闭该请求的 SDK 自动重试；工具动作数与模型请求数分开统计。此限制只作用于研究动作，不改变原问答的 LLM 配置。
- `events` 保存动作参数摘要（检索词可见）、结果引用、错误码、耗时和可获得的 Token 用量。Token 用量缺失时记为 `unavailable`。
- 连续检索无新证据或仅剩最后一次模型调用时，只允许 `finish_report`；未完成检索时不能提交报告。
- `finish_report` 校验引用 ID 是否属于当前任务。多文档比较题还检查每篇文档有引用、至少一条标为 `comparison` 且引用两篇文档的结论、至少一条标为 `limitation` 且引用两篇文档的结论。缺项时保留报告并设置 `status=partial`、`stop_reason=report_incomplete` 与 `question_coverage.gaps`；满足结构条件才是 `completed`。`verification_status=needs_semantic_review` 表示结构检查不能证明结论得到原文支持，仍需人工复核。
- `search_documents` 可传 `document_ids` 在已冻结范围内定向检索；越界或重复 ID 被拒绝。首次模型检索后，Harness 对证据账本中尚未覆盖的文档各补查一次，最多三篇，并为最终报告预留一次工具调用。补查记录为 `actor=harness` 的独立事件，计入工具次数但不计入模型动作数。补查使用原问题及单文档范围，仍可能漏召回相关证据。
- H1 的进程内存储仅保留为测试替身；当前 API 使用 H2 MongoDB 存储。
