# DocRAG Harness 演示脚本

更新时间：2026-10-18。建议 3～5 分钟，使用本地环境和已保存结果。

## 演示准备

1. 按 [README](../../README.md#一条命令启动推荐) 使用统一入口启动 API 和 research worker，打开 <http://127.0.0.1:8000/>。
2. 登录，选择已索引的 RAG、LoRA、CoT 三篇论文，准备一条已有研究记录与可展开的引用。
3. 免费模型运行可能需要数分钟，现场先展示已有报告，再提交新任务展示异步过程。
4. 打开本机 `eval/runs/harness/h4_pilot_20261018/overview.json`。H4 使用隔离实验集合，这些 JSON 不会自动进入前端历史记录。

## 0:00–0:30：项目定位

展示知识库、文档和历史记录。

> DocRAG 是一个多文档 RAG 应用。原有链路负责解析、版本化索引、混合检索和来源追溯；这轮增加单 Agent Harness，让模型能根据检索反馈继续找证据，并把执行状态保存下来。

## 0:30–1:10：普通问答

使用“问答”模式，展示已有事实回答和引用：

> LoRA 如何减少需要训练的参数？

展开来源，查看文件名、页码和原文。普通事实题可以直接使用原有 RAG。

## 1:10–2:10：深入研究

切换“深入研究”，沿用侧栏三篇文档，提交：

> 比较这三篇论文分别解决的问题、核心方法，以及实验结果为什么不能直接比较。逐项引用原文，证据不足的部分明确说明。

展示任务进入队列、worker 执行和可折叠的“研究过程”。随后切换已有研究报告，展开实际执行步骤。

> Harness 体现在运行循环：模型选择工具，运行层执行并反馈，模型再决定下一步。文档范围、索引代次、调用预算和停止条件由运行层管理；任务、步骤和证据由 MongoDB 保存，worker 独立执行。

不要求每次任务出现全部工具，也不把步骤数量当作回答质量。

## 2:10–2:50：报告、引用和连续研究

1. 展示报告，点击引用查看原文；如果状态为“部分完成”，如实展示保留的结果和缺口。
2. 在当前报告下输入“进一步解释 LoRA 与 RAG 的适用场景，沿用原文依据”，展示继续研究入口。提交后是关联上一任务的新任务，拥有新预算。
3. 说明继续研究沿用原文档范围和有限上下文；点击“新研究”后按当前侧栏范围发起独立任务。
4. 展示历史会话、研究记录折叠和删除按钮。演示删除时使用准备好的无用记录；运行中任务需先取消。

## 2:50–3:40：展示 H4 对照结果

打开 `overview.json`，聚焦三论文比较题：

| 方案 | 来源覆盖 | 模型请求 | 耗时 |
| --- | --- | --- | --- |
| 原有问答 A | 1 篇 | 3 次 | 178 秒 |
| 固定检索 B | 2 篇 | 1 次 | 66 秒 |
| Harness C | 3 篇 | 8 次 | 441 秒 |

> 这次比较题中，Harness 通过反馈检索覆盖了三篇文档，代价是更多调用和等待。三题九组最终记录里，八组有文本或报告，一组供应商 429 失败；其中一份报告部分完成。这是小规模演示对照，没有证明整体准确率提升。

## 常见现场情况

- **一直排队**：确认第二个终端的 research worker 正在运行，且与 API 使用同一配置。
- **模型较慢**：新任务单次请求最多 600 秒，总任务最多 90 分钟，含排队；旧任务保留原预算。展示已有结果即可。
- **429 或超时**：展示失败状态与保存的步骤，切换已有报告，不连续重试。
- **报告部分完成**：展示实际内容、原文证据和剩余缺口，不称为全部通过。

本轮交付为本地演示版；README 中的旧版线上部署和测试数量属于历史基础 RAG 记录。
