# DocRAG 三分钟演示脚本

## 演示前检查

1. 打开 <https://maoxiao-1205-medrag.hf.space/>，确认 `/health` 返回 `build_commit=8770e28ec88e5d7797e622117cd749eace20f168`。
2. 确认 `/ready` 返回 200；如果实例冷启动，等待就绪后再开始。
3. 使用已准备好的 PDF 或历史会话，现场不要临时上传大型文档。
4. 准备一个能展开 sources 的历史回答，网络或 LLM 限流时可直接展示历史结果。

## 0:00–0:25：项目定位

> DocRAG 是一个多文档 PDF RAG 应用。重点不只是调用大模型，而是把解析、索引版本、混合检索、重排、会话持久化和来源追溯连成完整链路。

展示首页、知识库和文档列表。

## 0:25–0:55：上传与索引

操作：上传 PDF，展示 `pending → parsing → indexing → completed`。

讲解：

> 上传接口返回 `202 + job_id`。系统用 `document_hash` 做重复识别，用 `index_fingerprint` 判断旧索引能否复用，新索引写入独立 generation，验证完成后才切换 active generation。

## 0:55–1:35：问答与来源

操作：打开文档会话，提问一个事实问题，展开 sources。

讲解：

> 查询先经过 Dense 或 Hybrid 召回，再通过 RRF 和 CrossEncoder 重排。回答会保存页码、文件名、chunk 和检索信息，历史消息查看时不会重新检索。

## 1:35–2:10：追问与任务路由

操作：继续一个带指代的追问，再展示总结或术语问题。

讲解：

> 系统只读取有限历史来补全追问，原问题仍保留在界面和消息中。Router 会选择 qa、summary、report、term 或 source_check；Summary 使用多个子查询扩大分散证据覆盖。

## 2:10–2:40：知识库与用户隔离

操作：切换知识库，展示多文档选择。

讲解：

> 会话可以检索整个知识库，也可以限定部分文档。JWT 登录后的 user_id 会参与每次资源校验，避免只相信前端传入的文档 ID。

## 2:40–3:00：验证边界

讲解：

> 当前 GitHub CI 和线上业务闭环已经通过，工程测试基线是 374 passed、9 skipped。最新固定 20 题 20/20 执行成功，但证据召回为 0.632、P95 约 199.9 秒，仍应定位为演示候选。

## 失败预案

- **冷启动**：先访问 `/health` 和 `/ready`，等待 ready 后再操作。
- **LLM 429/503**：停止连续重试，转为展示已保存历史会话和 sources。
- **索引失败**：展示 job 的 `failed` 阶段和错误信息，说明任务支持 retry。
- **网络不可用**：使用 README 截图、架构图和线上验收报告完成讲解。
