# DocRAG Agent 三分钟演示脚本

## 演示前准备

1. 提前打开线上页面，等待 `/health` 恢复正常，避免免费实例冷启动占用演示时间。
2. 使用已经索引过测试论文的演示用户 `docrag-eval-v1`。
3. 预先确认至少一个历史会话包含多轮问答和可展开的 sources。
4. 不在正式演示中现场索引大型 PDF；需要说明索引流程时展示界面、架构图和已有文档。
5. 保留 README 截图作为网络或免费模型限流时的备用材料。

## 0:00-0:25 项目定位

讲解：

> DocRAG Agent 是一个面向 PDF 文献阅读的 RAG 智能助手。它不只是调用大模型问答，还实现了 PDF 解析、向量检索、用户数据隔离、多轮会话、Query Rewrite、引用来源和 RAG 评估。

展示：项目首页和在线演示地址。

## 0:25-0:50 系统架构

讲解：

> PDF 上传后先经过按页解析和可选 OCR 回退，再完成文本切分、Embedding 和 Chroma 存储。提问时，系统结合最近几轮历史进行 Query Rewrite，然后执行向量召回、Rerank、Prompt 构造和大模型回答。用户、文档、会话和消息保存在 MongoDB。

展示：README 中的 Mermaid 架构图。

注意：不要逐个介绍 Python 文件，应围绕数据流和模块职责讲解。

## 0:50-1:15 文档与会话管理

操作：

1. 指向左侧历史文档列表。
2. 选择 `03_cot_paper.pdf`。
3. 展示该文档关联的历史会话。

讲解：

> 系统通过 user_id 隔离不同用户的数据，通过文件内容的 SHA-256 生成 document_hash，识别同一用户是否上传过相同文件，避免重复解析和索引。同一文档可以继续历史会话，也可以新建会话。

## 1:15-2:00 文献问答与引用

展示已有问题：

> CoT 在不同模型规模上的效果一致吗？

操作：展开回答下方的引用来源。

讲解：

> 回答基于当前文档检索到的片段生成。assistant 消息会保存当时使用的 sources，而不是查看历史时重新检索，因此回答可以追溯和复现。引用中保留页码、chunk 和检索距离，用户可以回到原文核验。

## 2:00-2:30 多轮追问

展示追问：

> 为什么小模型可能反而变差？

讲解：

> 当前问题省略了完整讨论对象。系统读取最近几轮历史，将追问改写成可独立检索的问题；前端仍展示用户原始问题，rewritten_query 只用于检索、日志和评估。历史负责理解上下文，当前检索到的文献片段才是事实依据。

## 2:30-3:00 评估与工程取舍

讲解：

> 我构建了 3 篇公开论文、19 道问题的小型评估集，统计执行成功率、HitRate、Recall 和 MRR。当前 HitRate@3 为 0.7692、Recall@3 为 0.6026、MRR@3 为 0.6410。事实题和证据核查相对稳定，主要不足是总结题和对比题的多证据覆盖及排序。我保留逐题结果，没有只展示整体平均值。

收尾：

> 这个项目的重点不是功能数量，而是把 PDF 解析、检索、生成、会话持久化、引用追溯、异常处理和评估串成一条可以演示和定位问题的工程链路。

## 演示失败预案

### 免费实例冷启动

先访问 `/health`，等待返回 200 后再进入页面。

### LLM 返回 429 或 503

不要连续重试。直接切换到已保存的历史会话，展示回答、sources 和持久化结果，并说明系统已区分供应商可用性与 RAG 质量。

### 现场网络不可用

使用 README 中的项目截图、架构图和评估结果完成讲解。
